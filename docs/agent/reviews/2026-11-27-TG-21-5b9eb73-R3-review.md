## F02 line of investigation

**Original UAT F02:** On Chrome 158 ChatGPT App Shell, classic `[data-message-author-role]` / `article[data-testid^="conversation-turn"]` were absent. DOM had multiple keep-alive conversation transcripts, making document-wide virtualized-turn enumeration unsafe.

**Source-level validation:**
- `getChatGPTMessages(doc)` retains both classic selectors before attempting the App Shell adapter.
- `getChatGPTConversationId()` extracts a path-based `/c/<id>` match, including `/g/<gpt-id>/c/<id>`, decoding the ID safely.
- `findActiveChatGPTAppShellContainer(doc)` looks for `data-chatgpt-conversation-selection-target` matching the URL conversation ID; if duplicates, it selects only a unique non-hidden/non-inert/non-aria-hidden/non-CSS-hidden match.
- Without an ID match, candidate selection uses `[data-thread-find-target="conversation"]` and `[data-rail-chat-transcript="true"]`, deduplicates nested matches, excludes hidden/inactive candidates and conflicting selection target IDs; requires **exactly one** candidate. Ambiguous/absent -> `null` -> `unavailable` / `Chưa nhận diện DOM`.
- `[data-conversation-role]` and fallback `[data-virtualized-turn]` queries occur only on the selected `container`, never globally on `document`. No fallback to `main.innerText`.
- Existing Claude extraction and copy-only behavior not modified.

**New regression test:** `tests/test_web_userscript.mjs` adds fixtures for simultaneous active/cached/hidden App Shell transcripts, URL switch by `pushState`, GPT-scoped conversation path, ambiguous project page, and no-container project page. Assertions ensure only target transcript is counted and ambiguity returns `Chưa nhận diện DOM`.

**Disposition:** **F02 CLOSED at source-review/fixture-design level**. No new blocking code defect identified in the R3 diff.

**Residual behavior to validate during T9:** The legacy selector route still queries document-wide by design, and a uniquely matched ID container is returned without an explicit visibility test; observe these when testing real pages with mixed legacy/App Shell DOM and inactive keep-alive panels. If wrong transcript data appears, open a targeted follow-up. This is not an observed defect in the candidate fixtures.
